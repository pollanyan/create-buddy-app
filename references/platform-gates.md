## 二、主体类型 → 能做什么（最关键的一张表）

| 资产 | 个人主体 | 企业主体 | 组织机构主体 |
|---|---|---|---|
| 技能 Skill | ✅ | ✅ | ✅ |
| 专家 Expert / 专家团 | ✅ | ✅ | ✅ |
| 连接器 Connector | ⚠️ 见下方实测 | ✅ | ✅ |
| **Buddy 应用** | ❌ | ✅ | ✅（能力等同企业主体） |
| 硬件接入 | ❌ | ✅ | ✅ |
| 第三方应用接入 | ❠️ | ✅ | ✅ |

**认证路径**

- **个人认证**：身份证 + 实名手机号 + 邮箱 + 人脸核身。一个身份证全平台只能认证一个个人主体，
  每账号最多一个个人主体。
- **企业认证**（持营业执照的经营主体，含**个体工商户**）三选一：
  法人本人扫码人脸核身 / 复用腾讯云已认证主体 / 复用已认证公众号或小程序主体（后两者免扫脸）。
- **其他组织机构认证**（无营业执照）：事业单位、政府机关、社会团体、民办非企业单位、基金会、
  律所、媒体等；凭统一社会信用代码证书 + 管理员实名。**能力与企业主体一致**（可发布 Buddy 应用）。

> ⚠️ **实测坑**：个人主体提交**连接器**时，后端会返回
> 「个人主体暂不支持创建连接器，请升级为企业主体后使用」。
> 错误文案来自**后端**（前端包里没有这句），`create` / `republish` / `resubmit` 三种动作都被拦。
> 这不是配置问题，是主体策略——别反复重试，直接去办企业/组织主体。

> ⚠️ 认证通过后**必须补齐「开发者信息」**（头像 / 昵称 / 简介 / 联系方式），
> 否则后台的新建资产入口不解锁（表现为「创建」按钮点了没反应或报 profile 状态不对）。

## 三、资产之间的关系

```
连接器（提供工具能力，远程 MCP）
    └── 被 Buddy 应用在「市场配置 → 连接器」里选配
专家 / 专家团 / 技能（人格与流程）
    └── 被 Buddy 应用在「市场配置 → 专家/技能」里选配
Buddy 应用（行业 Harness：工作模式 + 场景胶囊 + 模型池 + 能力市场）
    └── 上架后出现在右上角「发现应用」
```

**要出现在「发现应用」，完整链路是**：
发布连接器 → 创建 Buddy 应用并选配它 → 提交审核 → 上架。
Buddy 应用的依赖写法支持 `connector:<plugin>` / `custom-mcp:<name>` / `mcp:<name>`，
所以**云端应用 + 本地连接器是官方支持的组合**。

「发现应用」是云端下发的只读目录（`/api/v1/open-platform/buddy_application?scene=recent|recommended`），
**本地无法注入条目**。

## 四、Buddy 应用五模块配置清单

Buddy 应用**不走 zip 上传**，是网页端逐模块填表单。下面是逐字段清单模板
（完整可填写版本见 `assets/application.template.json`，提交前用 `scripts/check_buddy_app.py` 自检）。

### 模块 1 · 创建应用

| 配置项 | 内容 | 备注 |
|---|---|---|
| 应用 ID | 系统生成 | 不可修改 |
| 应用头像 | 256×256 | |
| 应用名称 | 面向用户的中文名 | |
| 应用简介 | 一段话定位与核心能力 | |
| 授权回调 URL | `https://<你的域名>/oauth/callback` | 需自己实现接收授权码的 HTTPS 端点 |
| 可信 Origin | `https://<你的域名>` | |

创建后拿到 **Client ID / Client Secret**，**Secret 只完整展示一次**，立刻保存。

### 模块 2 · 首页配置

- **Slogan**：欢迎语标题（中英）
- **场景胶囊（2~5 条）**：必须是**用户真实口语**，可绑定专家/Skill/连接器/案例
- **工作模式（2~4 个）**：每个含 `System Prompt` + `预绑定 Skill` + `适用场景`
  - 场景胶囊 ≠ 工作模式：胶囊是"用户会怎么说"，工作模式是"助手以什么角色工作"
- **内置连接器**：仅限支持 OAuth 认证的 MCP，用户首次进入会走「绑定应用」弹窗跳 OAuth

### 模块 3 · 市场配置

| 板块 | 引用 | 备注 |
|---|---|---|
| 专家 / 专家团 | ID | 引用需与资产的 source/name 一致 |
| 技能 | Skill 列表 | |
| 连接器 | 连接器列表 | **派工台挂这里** |
| 精选场景 | 关联专家或专家团 | 可选 |

引用的资产必须**已上架或同批生成**。

### 模块 4 · 其他配置

- 跳过首次绑定应用授权：开启 / 关闭（应用不使用绑定能力时可开）
- 绑定应用授权文案（开启绑定时必填）
- 输入框占位符：中文 / 英文
- 模型池：勾选模型、排序、设默认

### 模块 5 · 预览调试

- [ ] **每次退出配置前导出配置 JSON 备份**（唯一的回滚手段）
- [ ] 经预览链接下载对应版本 WorkBuddy 端验证
- [ ] 提交审核

**设计规格（数值不得改动）**
- 应用 icon：16px×16px、线宽 1.2px、有断口、圆角平滑 100%
- 专家页精选场景背景图：1000×910px、底图 + 3 层渐变蒙层、日夜间 2 套

**发布流程七节点**：创建应用 → 基础信息 → 创建审核 → 分模块配置 → 预览调试 → 提交审核 → 发布上线

## 五、分发路径

| 方式 | 做法 | 可见范围 |
|---|---|---|
| 公开上架 | 发布范围勾「公开」 | 全平台用户可见 |
| 企业内分发 | 勾「发布到企业」→ 建**企业单**（企业 ID/名称、全员制或席位制、授权时长）→ 授权链接发给企业管理员 → 管理员在 `www.workbuddy.cn/admin` 确认 | 该企业员工 |

分发到企业**不需要企业主体**，只要资产本身能上架 —— 但 Buddy 应用本身需要企业/组织主体才能创建。
